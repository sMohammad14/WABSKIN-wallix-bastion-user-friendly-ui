به پیشنهاد یکی از دوستان، تصمیم گرفتم یک پوسته کاربر پسند برای WALLIX Bastion بنویسم. که فعلا از قسمت Device ها با یک سری امکانات شروعش کردم.

اگر با ولیکس کار کرده باشید به طور کامل با ضعف های پوسته اش آشنا هستید. پنجره های کوچک و متنوع که در قالب Div ها برای یک عملیات ساده ظاهر میشن و خسته کننده هستند. عدم امکان تغییرات به صورت دسته ای و یک باره، به عنوان مثال اگر تصمیم به تغییر policy تعدادی Device داشته باشید، باید تک تک اقدام کنید در صورتی که در نرم افزارهای مشابه دیگه مانند PAM360 این امکان برای شما فراهم هست و به راحتی میتونید یک عملیات خاص رو به صورت دسته ای برای تعدادی آبجکت انجام بدید.

 این پروژه که مبتنی بر API های سامانه Bastion توسعه داده و نیاز به سرور و دسترسی خاصی نداره به راحتی با یک یوزر Admin با دسترسی محدود و کنترل شده کار میکنه،  میتواند  4 مؤلفه از Device رو که شامل نام، آدرس، توضیحات و برچسب هست رو اصلاح کنه. همچنین میتونید با این پروژه سرویس های هر Device رو هم به خوبی و راحتی مدیریت کنید. امکاناتی که در حال حاضر با این پروژه در دسترس هست فعلا شامل موارد زیر هست:

✅اصلاح نام Device

✅اصلاح IP/FQDN/SubnetIP

✅اصلاح Description

✅اصلاح Alias

✅اصلاح Sub-Protocol های Service های منتسب به Device و شماره پورت

✅حذف Service های منتسب به Device


امکاناتی که در حال حاضر در دسترس نیست:

❌اضافه کردن Device

❌حذف Device

❌اضافه کردن Service


💎تمام پالیسی ها برای کار با Device ها در نظر گرفته شده، مانند کاراکترهای مجاز برای نام گذاری، بررسی رعایت فرمت IP/FQDN/SubnetIP برای آدرس سامانه های مقصد و ...
قدم بعدی اضافه کردن امکاناتی هست که فعلا برای Device ها پشتیبانی نمیشه (ذکر شد)

در پایین صفحه یک کنسول قرار داده شده تا تمام لاگ ها و خظاهای احتمالی قابل مشاهده و خطایابی باشه. این ابزار به گسترش پروژه بسیار کمک خواهد کرد.


💡و قدم های آتی شامل گسترش پروژه برای تمام موارد (کاربران، گروه های کاربری، گروه های سرور ها و Authorization) خواهد شد.


**🚨باگ های کشف شده:**

⚠️اضافه کردن Device بدون نام. نکته جالب توحه این هست که شما میونید به کمک API ها Device اضافه کنید که ام نداشته باشه. کی از خظرات جدی میتونه اشغال فای لایسنس و عدم مشاهده چنین دستگاه هایی داخل UI سامانه باشه. ر حالی که در UI چنین دستگاهی وجود نداره ولی ممکن هست در دسترس باشه (نیاز به بررسی). این مورد برای سامانه PAM که خودش مسئول مدیریت دسترسی به سامانه های حیاتی سازمان هاست قابل توجه هست و سازمان ها باید با دقت یشتری سراغ چنین محصولاتی برن و ریسک هاش رو بپذیرن، چون معمولا چنین سکوهایی به دلیل پاسخگو نبودن در داخل کشور، هیچ مسئولیتی رو تقبل نخواهند کرد.

⚠️تغییر شماره Port سرویس یک Device که کاربر اجازه دسترسی به آن را ندارد. اگر کاربری از طریق گروه ها به یک مقصد دسترسی داشته باشد ولی این دسترسی از قسمت Authorization محدود شده باشد، کاربر میتواند از طریق API ها شماره Port را تغییر دهد. ریسک و اهمیت این موضوع زمانی خودش رو نشون میده که کاربر صرفا End-User میتونه به واسطه مشاهده یک Device (به دلیل ساختار ایجاد دسترسی در PAM) کانفیگ های Device رو تغییر بده. فرض کنید یک Device روی یک شماره پورت صرفا به ارائه سرویس به کاربران نوع User میپردازد و روی یک شماره پورت دیگر، به کاربران Administrator یا Root خدمات میدهد.با یک تغییر پورت ساده، کاربر میتواند به راحتی دسترسی خود را ارتقا داده و ریسک های بشدت خطرناکی برای سازمان ایجاد کند. ریسک هایی که اتفاقا به دلیل تغییری ایجاد شده اند که PAM خود مسئول مدیریت و محافظت چنین ریسک هایی هست.




این پروژه در حال توسعه هست، و مسئولیت بهره برداری از این پروژه و استفاده از آن با کاربر استفاده کننده هست و توسعه دهنده هیچ مسئولیتی نمیپذیرد.
